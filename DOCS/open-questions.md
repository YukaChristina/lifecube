## 優先度: 高

### デプロイ方針

以下は暫定決定済みです。

- 環境名は Expo / EAS 標準に合わせて `development` / `preview` / `production` に統一する。
- `preview` はテストユーザー確認用の環境とし、iOS では TestFlight 配布に使う。
- Android の `preview` は Firebase App Distribution で配布し、EAS Build では APK を生成する。
- `development` は `preview` / `production` と別の bundle identifier / package name にする。
- 環境切替は `.env.local`、EAS Environment Variables、`APP_VARIANT`、`app.config.ts` を使う。

確認したいこと:

- iOS と Android の配布設計を同時に進めるか。
- Apple Developer Program と Google Play Console の設定を誰が担当するか。
- EAS Update をいつ導入するか。
- Firebase App Distribution の Android App ID、配布グループ、アップロード担当、リリースノート運用をどう管理するか。
- production submit の承認フローをどうするか。

### データ保存

MVP では、写真セットの紐付けと合成パターン保存のために `expo-sqlite` のローカルDBを使う方針です。

画像本体は、LifeCube 内アルバム用にアプリ内保存領域へ保存します。端末の写真アプリには成果物画像だけを保存します。前後カメラ撮影では合成後写真、背面カメラのみ撮影では背面写真が成果物画像です。詳細は `ui-ux/storage-and-platform-feasibility.md` を参照してください。

DB拡張は、今後の細かな移行を繰り返さないよう、実装前に設計検討タスクとして扱います。

確認したいこと:

- 既存DBへ `captureMode`、`orientation`、`composedWidth`、`composedHeight`、`pattern null` 許容を追加する移行方法。
- 背面カメラのみ撮影で、`frontLocalUri`、`pattern`、成果物画像をどう表現するか。
- iOS の Photos asset id と Android の MediaStore uri/id が、`composedAssetId` としてどの程度安定して扱えるか。
- ユーザーが写真アプリ側で画像を削除、編集、移動したときにどう扱うか。
- アプリ再インストール後も残すべきデータがあるか。
- プライベートまたは機微なデータを扱うか。
- クラウド同期が必要になるか。
- オフラインファーストの挙動が必要か。

### UI方向性

UI/UX の大枠は、スマホファーストのカメラ体験を中心に進めます。

起動直後はカメラ画面、撮影後は4秒間の合成プレビュー、アルバムは日付ごとの写真セット一覧を基本にします。世界観は Quiet Pastel / Soft Editorial を候補にします。

詳細は `ui-ux/mvp-ui-ux.md` と `ui-ux/wireframes.md` を参照してください。

確認したいこと:

- 枠線、注意メッセージ、タブ、ボタンの具体的な見た目。
- 実機写真に対して、暫定の合成境界線カラーが合うか。
- 縦向き写真と横向き写真が混在するアルバム一覧を、正方形グリッド、縦横比を保つ単純グリッド、masonry風レイアウトのどれで進めるか。
- iPad 横向きで 2 ペイン構成を採用するか。
- 背面カメラのみモードの設定名をどうするか。
- ガイド画面に最初に載せる撮影手順や説明の範囲をどうするか。
- カメラが返す画像サイズや元写真のアスペクト比に応じて、将来的に合成画像の出力サイズをどこまで可変にするか。
- 高画質保存を優先する場合、合成画像の標準解像度をどこまで上げるか。
- ホーム、アルバム、撮影UIに適用するテーマカラーの最終案。
- 参考にする画面やサービスはあるか。

### カメラ待機とバックグラウンド動作

カメラ画面で長時間「シャッター」を待つ体験を前提に、音楽併用を検討します。スリープ抑止は実装済みで、実機で正しく動作することを確認済みです。バックグラウンド音声検知はOS制約が強いため、技術検証を先に行います。

確認したいこと:

- LifeCube 前面利用中に、他アプリの音楽を止めずに音声認識できるか。
- バックグラウンドで「シャッター」を検知できるか。
- Android の常駐通知を出した場合、ユーザー体験として許容できる文言や表示は何か。
- iOS でバックグラウンド音声検知が現実的に成立するか。
- バックグラウンド音声検知を採用しない場合の代替体験をどうするか。

### 顔検出

円形くり抜きでは、内側写真の人物の顔が円形部分の中央に入るようにしたいです。複数人が写る場合は、最も大きい顔を優先します。

確認したいこと:

- どの顔検出ライブラリを採用するか。
- development build の作り直しや config plugin 変更が必要か。
- 顔検出に失敗した場合、中央寄せの円形くり抜きへフォールバックするか。
- 顔を中央へ寄せるだけで十分か、円形部分で見やすいようにズーム調整も行うか。
