## 優先度: 高

### デプロイ方針

現在はローカルの Expo 開発コマンドで確認しており、EAS profile はありますが、実際の配布・デプロイまでの流れは未定義です。

確認したいこと:

- 最初の配布目標は、内部配布、TestFlight、Google Play 内部テスト、公開ストア配布のどれか。
- iOS と Android の配布設計を同時に進めるか。
- Expo Application Services を、両プラットフォームの build / submit の標準経路にするか。
- Apple Developer Program と Google Play Console の設定を誰が担当するか。

### バックエンドとクラウド基盤

将来的にバックエンドが必要になる可能性はありますが、まだ設計はありません。

確認したいこと:

- どのデータを端末外へ出す必要があるか。
- ユーザー認証が必要か。
- 複数端末での同期が必要か。
- 生成メディアをクラウド保存する必要があるか。
- カスタム API サーバーが必要か、BaaS で足りるか。
- どのクラウドプロバイダーやバックエンドサービスを候補にするか。

### データ保存

MVP では、写真セットの紐付けと合成パターン保存のために `expo-sqlite` のローカルDBを使う方針です。

画像本体は、LifeCube 内アルバム用にアプリ内保存領域へ保存します。端末の写真アプリには合成後写真だけを保存します。詳細は `ui-ux/storage-and-platform-feasibility.md` を参照してください。

確認したいこと:

- iOS の Photos asset id と Android の MediaStore uri/id が、`composedAssetId` としてどの程度安定して扱えるか。
- ユーザーが写真アプリ側で画像を削除、編集、移動したときにどう扱うか。
- アプリ再インストール後も残すべきデータがあるか。
- プライベートまたは機微なデータを扱うか。
- クラウド同期が必要になるか。
- オフラインファーストの挙動が必要か。

### 状態管理

グローバル状態管理ライブラリはまだ選定していません。

確認したいこと:

- 当面はローカル state で十分か。
- サーバー状態の管理が重要になるか。
- Zustand、Redux Toolkit、TanStack Query、React Context、その他のどれを候補にするか。

### UI方向性

UI/UX の大枠は、スマホファーストのカメラ体験を中心に進めます。

起動直後はカメラ画面、撮影後は4秒間の合成プレビュー、アルバムは日付ごとの写真セット一覧を基本にします。世界観は Quiet Pastel / Soft Editorial を候補にします。

詳細は `ui-ux/mvp-ui-ux.md` と `ui-ux/wireframes.md` を参照してください。

確認したいこと:

- 枠線、注意メッセージ、タブ、ボタンの具体的な見た目。
- 実機写真に対して、暫定の合成境界線カラーが合うか。
- iPad 横向きで 2 ペイン構成を採用するか。
- 参考にする画面やサービスはあるか。
