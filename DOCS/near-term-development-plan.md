# 直近開発計画

この文書は、足元で優先する開発課題と実装順を管理します。

詳細仕様は分野別DOCSに置き、この文書では優先度、依存関係、実装の切り方を短く整理します。古くなった内容は、決定事項を該当DOCSへ移したうえで整理します。

## 優先度

### 完了済み

- リファクタリング
  - `app/(tabs)/index.tsx` に集まっていた撮影フロー、音声トリガー、プレビュー復帰、保存処理、設定参照を小さく分けました。
  - UI、音声、権限、前後カメラ撮影、プレビュー、合成、保存セッションを分離し、以後のカメラ、合成、保存変更が1つの画面ファイルへ集中しにくい状態にしました。

### P0: 次に着手する基盤と体験改善

- DB拡張
  - 横向き合成と背面カメラのみモードに備え、写真セットに撮影モード、向き、出力サイズを保存できるようにします。
  - 既存データは `dual`、`portrait`、`1080 x 1920` として扱います。
- 合成写真の縦横対応
  - 端末が縦向きの場合は `9:16`、横向きの場合は `16:9` で合成画像を出力します。
  - アルバムの横向きサムネイルは横長比率のまま表示します。
- デフォルト合成パターン変更
  - デフォルトを「斜めカット」から「円形くり抜き」に変更します。
- 背面カメラのみモード
  - 設定から、前後カメラ撮影と背面カメラのみ撮影を切り替えられるようにします。
  - 設定名は未決定です。
  - 背面カメラのみの場合も LifeCube アルバムと端末の写真アプリの両方に保存します。
- 撮影後プレビューの4秒進捗表示
  - 4秒後にカメラへ戻る挙動を、控えめな進捗バーで見えるようにします。
- 撮影UIの整理
  - 撮影ボタンの視覚的な主張を下げ、音声トリガーを中心にした体験へ寄せます。
  - 「音声認識中」のラベルは、より控えめな状態表示へ置き換えるか削除します。
- スリープ抑止
  - カメラ待機中に画面がスリープしないようにします。

### P1: 実機で改善幅を見る課題

- 前後カメラ切替の高速化
  - 固定 `500ms` 待ちをやめ、`onCameraReady`、保存待ち分離、`takePictureAsync` options を使って短縮します。
  - `quality` 低下や `skipProcessing` は実機で画質、向き、速度を比較して判断します。
  - まず Expo の範囲で最適化し、ネイティブ対応はその後に判断します。
- 音楽併用
  - LifeCube を前面で使いながら、他アプリの音楽再生を止めない挙動を検証します。
- テーマ調整
  - ホーム、アルバム、撮影UIの背景色とテーマカラーを整理します。

### P2: 技術検証から始める課題

- バックグラウンド音声検知
  - LifeCube がバックグラウンドにいる状態でも「シャッター」を検知できるか検証します。
  - Android で常駐通知が必要になる場合は許容します。
  - OS制約が強い場合は、機能を諦める判断も候補にします。
- 円形くり抜きの顔中心補正
  - 内側写真に複数人が写る場合は、最も大きい顔を円形部分の中央に配置します。
  - 顔検出ライブラリの選定と development build への影響を先に確認します。

## 推奨実装順

1. 完了: リファクタリングで、撮影フロー、音声、保存、合成、設定を分離する。
2. DB拡張と既存データ移行を入れる。
3. 縦横合成、円形くり抜きデフォルト、背面カメラのみモードを実装する。
4. 撮影後4秒バー、撮影ボタン、音声状態表示、スリープ抑止を入れる。
5. 前後カメラ切替速度と音楽併用を実機で検証する。
6. バックグラウンド音声検知と顔検出は、技術検証の結果を見て採否を決める。

## 再ビルド判断

通常の JS / TS / UI 変更だけであれば development build の作り直しは不要です。

以下は development build の作り直しが必要になる可能性があります。

- 新しい Expo module または React Native native module の追加
- `app.config.ts` の権限、plugin、background mode 変更
- 顔検出ライブラリの追加
- バックグラウンド音声検知のためのネイティブ設定追加
- スリープ抑止で新しい native module を追加する場合
