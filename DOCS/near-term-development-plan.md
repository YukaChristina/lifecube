# 直近開発計画

この文書は、足元で優先する開発課題と実装順を管理します。

詳細仕様は分野別DOCSに置き、この文書では優先度、依存関係、実装の切り方を短く整理します。古くなった内容は、決定事項を該当DOCSへ移したうえで整理します。

## 優先度

### 完了済み

- リファクタリング
  - `app/(tabs)/index.tsx` に集まっていた撮影フロー、音声トリガー、プレビュー復帰、保存処理、設定参照を小さく分けました。
  - UI、音声、権限、前後カメラ撮影、プレビュー、合成、保存セッションを分離し、以後のカメラ、合成、保存変更が1つの画面ファイルへ集中しにくい状態にしました。
- デフォルト合成パターン変更
  - デフォルトを「斜めカット」から「円形くり抜き」に変更しました。
- スリープ抑止
  - カメラ待機中に画面がスリープしないようにしました。
  - 実機で正しく動作することを確認済みです。

### P0: 次に着手する修正と体験改善

- アルバム詳細の削除確認修正
  - 詳細画面の「削除する」は確認ダイアログを出し、確定時に削除処理を実行する状態へ戻します。
  - 端末の写真アプリ側に保存済みの成果物画像は、MVP初期では削除しません。
- 撮影後プレビューの4秒進捗表示調整
  - 4秒後にカメラへ戻る進捗バーは実装済みです。
  - 直感に合わせ、進捗表示は左から右へ進む形に修正します。
- 撮影UIの音声案内整理
  - 音声状態の小さいドット表示は意味が伝わりにくいため削除します。
  - 代わりに、`「シャッター」と言うと撮影します` のような控えめな案内文を表示します。
  - この文言は仮のものです。将来的に「シャッター」以外の音声トリガーを追加する可能性があります。
- ガイドタブ追加
  - 下部タブを `カメラ / アルバム / ガイド / ホーム` の順にします。
  - ガイドは撮影方法を閲覧するための補助画面として追加します。
  - 内容は後で整理します。初期実装では、簡素な撮影手順のたたき台を置きます。

### P0: 設計を詰めてから実装する課題

- DB拡張設計
  - 今後の細かなDB拡張を繰り返さないよう、実装前に拡張範囲を整理します。
  - 横向き合成、背面カメラのみモード、成果物画像サイズ、将来の保存拡張をまとめて検討します。
  - 既存データ移行方針もこの設計の中で決めます。
- 背面カメラのみモードの保存モデル整理
  - 撮影の意味合いは、前面カメラへ切り替えず背面写真1枚を成果物として保存する方向で確定です。
  - DB拡張と合わせて、`frontLocalUri`、`pattern`、成果物画像の扱いを保守しやすい形に整理します。
- アルバム表示方式検討
  - 縦長写真と横長写真を混在表示する方式は未決定です。
  - 候補は、正方形グリッド、縦横比を保つ単純グリッド、masonry風の可変レイアウトです。
  - 技術難度と保守性を見て、DB拡張設計と合わせて判断します。
- 合成写真の縦横対応の残り
  - 縦向きは `9:16`、横向きは `16:9` の成果物画像を生成する方向です。
  - 合成出力だけでなく、DB保存、詳細表示、アルバム表示まで含めて完了扱いにします。

### P1: 実機で改善幅を見る課題

- 前後カメラ切替の高速化
  - 固定 `500ms` 待ちをやめ、`onCameraReady`、保存待ち分離、`takePictureAsync` options を使って短縮します。
  - `quality` 低下や `skipProcessing` は実機で画質、向き、速度を比較して判断します。
  - まず Expo の範囲で最適化し、ネイティブ対応はその後に判断します。
- 音楽併用
  - LifeCube を前面で使いながら、他アプリの音楽再生を止めない挙動を将来検証します。
  - 現時点では未完了の将来対応として扱います。
- テーマ調整
  - ホーム、アルバム、撮影UI、ガイドの背景色とテーマカラーを整理します。

### P2: 技術検証から始める課題

- バックグラウンド音声検知
  - LifeCube がバックグラウンドにいる状態でも「シャッター」を検知できるか検証します。
  - Android で常駐通知が必要になる場合は許容します。
  - OS制約が強い場合は、機能を諦める判断も候補にします。
- 円形くり抜きの顔中心補正
  - 内側写真に複数人が写る場合は、最も大きい顔を円形部分の中央に配置します。
  - 顔検出ライブラリの選定と development build への影響を先に確認します。

## 推奨実装順

1. 完了: リファクタリング、円形くり抜きデフォルト化、スリープ抑止。
2. アルバム詳細の削除確認、4秒進捗バーの方向、音声案内表示を修正する。
3. ガイドタブと簡素なガイド画面を追加する。
4. DB拡張、背面カメラのみ保存モデル、アルバム表示方式をまとめて設計する。
5. 設計に沿ってDB移行、保存処理、アルバム表示、詳細表示を実装する。
6. 前後カメラ切替速度と音楽併用を実機で検証する。
7. バックグラウンド音声検知と顔検出は、技術検証の結果を見て採否を決める。

## 再ビルド判断

通常の JS / TS / UI 変更だけであれば development build の作り直しは不要です。

以下は development build の作り直しが必要になる可能性があります。

- 新しい Expo module または React Native native module の追加
- `app.config.ts` の権限、plugin、background mode 変更
- 顔検出ライブラリの追加
- バックグラウンド音声検知のためのネイティブ設定追加
