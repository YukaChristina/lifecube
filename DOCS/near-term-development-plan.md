詳細仕様は分野別DOCSに置き、この文書では優先度、依存関係、実装の切り方を短く整理します。古くなった内容は、決定事項を該当DOCSへ移したうえで整理します。

## 優先度

### 完了済み

- リファクタリング
  - `app/(tabs)/index.tsx` に集まっていた撮影フロー、音声トリガー、プレビュー復帰、保存処理、設定参照を小さく分けました。
  - UI、音声、権限、前後カメラ撮影、プレビュー、合成、保存セッションを分離し、以後のカメラ、合成、保存変更が1つの画面ファイルへ集中しにくい状態にしました。
- デフォルト合成パターン変更
  - デフォルトを「斜めカット」から「円形くり抜き」に変更しました。
- スリープ抑止
  - カメラ待機中に画面がスリープしないようにしました。
  - 実機で正しく動作することを確認済みです。
- アルバム詳細の削除確認修正
  - 詳細画面の「削除する」は確認ダイアログを出し、確定時に削除処理を実行する状態へ戻しました。
  - 端末の写真アプリ側に保存済みの成果物画像は、MVP初期では削除しません。
- 撮影後プレビューの4秒進捗表示調整
  - 4秒後にカメラへ戻る進捗バーは、左から右へ進む形に修正しました。
  - 実機確認結果を踏まえ、進捗バーの高さは8pxにしました。
- 撮影UIの音声案内整理
  - 音声状態の小さいドット表示は意味が伝わりにくいため削除しました。
  - 代わりに、`「シャッター」と言うと撮影します` の控えめな案内文を表示します。
  - この文言は仮のものです。将来的に「シャッター」以外の音声トリガーを追加する可能性があります。
- ガイドタブ追加
  - 下部タブを `カメラ / アルバム / ガイド / ホーム` の順にしました。
  - ガイドは撮影方法を閲覧するための補助画面として追加しました。
  - 初期実装では、簡素な撮影手順と保存・削除時の注意を置いています。
- DB拡張と背面カメラのみ保存モデル
  - `photo_sets` を schema version 2 にし、既存データを移行する方針で実装しました。
  - `captureMode`、`orientation`、`composedWidth`、`composedHeight` を保存します。
  - 背面カメラのみ撮影では `frontLocalUri`、`pattern`、内側写真フォーカス項目を `null` とし、背面写真を成果物画像として保存します。
  - 前後カメラ撮影では、内側写真フォーカスのデフォルトを `0.5 / 0.5 / 1.0` として保存します。
- 撮影結果ベースの縦横判定
  - 新規撮影では、画面レイアウトの縦横ではなく、カメラが通知する撮影時の向きを優先して `orientation` を保存します。
  - カメラ向き通知が取得できない場合は、背面カメラ撮影結果の `width` / `height` を fallback にします。
  - 横向き撮影では、成果物画像とアルバムタイルが横長扱いになるようにします。
  - 既存の誤判定済み写真は、今回は修正対象外とします。
- アルバムUI実装
  - アルバム一覧を、4列ベースの自前軽量 Mosaic / Quilted grid に置き換えました。
  - 日付ごとのセクション、日付順、成果物画像だけを表示する方針は維持しています。
  - 配置ロジックはUIから分離し、`PhotoSet` 配列からタイル位置を返す純粋関数として実装しました。
  - 縦長写真は `1列 x 2行`、横長写真は `2列 x 1行`、正方形に近い写真は `1列 x 1行` として扱います。
  - 一覧サムネイルは `cover` 表示、詳細画面は `contain` 表示を維持しています。
- 斜めカットの曲線化
  - 斜めカットは、直線的な境界ではなく、3次ベジェ曲線で分割します。
  - 縦向きでは右上から左下へ抜ける曲線にします。横向きでは縦向きの基準形を横へ倒した見え方にし、単純な横引き伸ばしで上下分割に近づきすぎないようにしました。
  - 曲線の上側に近い領域に外側写真、反対側に内側写真を配置します。
  - `features/photo-sets/diagonal-composition.ts` で、合成処理とホームの合成パターン選択UIが同じ曲線境界とクリップ領域を使うようにしました。
  - ホームの合成パターン選択UIは、並び順を `円形くりぬき / 斜めカット / 左右分割` にし、3パターンの境界線色とトーンを揃えました。
  - 既存の保存済み斜めカット画像は自動再合成しません。新規撮影または詳細画面での再合成から新しい曲線を使います。
- アルバム詳細の合成パターン切り替え順序整理
  - ホームのデフォルト合成パターン設定に合わせ、アルバム詳細の切り替え順を `円形 / 斜め / 分割` にしました。
  - 表示は現行の2文字ラベルボタンを維持しています。
  - 画像だけの選択UIや左右スワイプでの切り替えは、後続の抜本的な詳細画面UI検討で扱います。
- 横長撮影後プレビューの拡大表示修正
  - 横長撮影の撮影後プレビューで、`cover` 表示により中央だけが大きく切り抜かれる問題を修正しました。
  - 撮影後プレビューには撮影時の `orientation` を渡し、横向きでは `contain` 表示で成果物画像全体を見せます。
  - 縦向き撮影の撮影後プレビューは、現行の `cover` 表示を維持します。
- 横向き撮影時の前面写真向き診断と前後カメラ切替の暫定高速化
  - 横向き撮影で前面写真だけ縦扱いまたは90度回転になる問題は、背面/前面それぞれの `width` / `height` と期待する向きの一致を一時診断ログで比較して原因を切り分けました。
  - Android では `takePictureAsync({ exif: true })` が画像の回転補正処理に影響するため、通常の撮影フローでは使わない方針にします。
  - 背面から前面へ切り替えた後の固定 `500ms` 待ちはやめ、前面カメラの `onCameraReady` を待ってから撮影する形にしました。
  - この暫定高速化は実機確認済みのため、足元の前後カメラ切替対応は完了扱いにします。
  - 診断ログは原因確認後に削除しました。今後同種の調査では、一時ログを小さく集約し、解決後に消せる形にします。
- 音声シャッター認識設定の軽量化
  - トリガー語は当面 `シャッター` のままにします。
  - 音声認識には `contextualStrings: ['シャッター']` と `maxAlternatives: 1` を指定し、認識ヒントを渡しつつ返却候補を1件に絞りました。
  - 音声認識が終了した場合の再起動待ちは `100ms` にしました。
  - 実機では「シャッター」と言ってから体感約300msの結果待ちが残るため、MVPでは許容し、さらなる低遅延化は将来改善扱いにします。

現時点では、直近で追加実装するP0課題はありません。

### P1: 実機で改善幅を見る課題

- 音声シャッターのさらなる低遅延化
  - 現行の `expo-speech-recognition` とOS標準音声認識では、`result` イベント待ちによる体感遅延が残ります。
  - MVPでは現在の約300msを許容し、必要性が高まった時点で `soundstart` / `result` / `takePhoto` 開始の一時ログ計測を行います。
  - 追加候補は、端末内音声認識、専用キーワード検知、`soundstart` での先行UI反応です。
  - 専用キーワード検知は native module、モデル管理、電池消費への影響があるため、導入前に技術検証します。
- 音楽併用
  - LifeCube を前面で使いながら、他アプリの音楽再生を止めない挙動を将来検証します。
  - 現時点では未完了の将来対応として扱います。
- テーマ調整
  - ホーム、アルバム、撮影UI、ガイドの背景色とテーマカラーを整理します。
- 横向き時のカメラUI整理
  - 端末を横持ちしたときに、撮影案内文や撮影後プレビューの進捗表示が読みにくい問題を整理します。
  - まずは写真データの縦横判定を優先し、UIの横向き最適化は後続課題として扱います。
  - 横長撮影後プレビューは、現状では中央切り抜きを避けるため `contain` 表示にしていますが、縦長画面内に縮小表示され上下に黒帯が出ます。
  - 将来的には、横長撮影時だけ横長基準のプレビュー枠を使うか、プレビュー画面自体を横向きに切り替えるかを検討します。
  - 目標は、横長撮影時に合成画像全体を保ちつつ、横長画面いっぱいに近い大きさで確認できる状態にすることです。

## 再ビルド判断

通常の JS / TS / UI 変更だけであれば development build の作り直しは不要です。

以下は development build の作り直しが必要になる可能性があります。

- 新しい Expo module または React Native native module の追加
- `app.config.ts` の権限、plugin、background mode 変更
- 顔検出ライブラリの追加
- バックグラウンド音声検知のためのネイティブ設定追加
