### P0: 技術検証（実装前に必ず確認する）

P0 は①→②→③の順に進める。①②はリスクが低く早く結果が出る。③は最も時間がかかるため、①②を進めながら並行して調査する。

#### ① 複数音声トリガー検知（再ビルド不要・今すぐ可能）

現行の `expo-speech-recognition` を複数ワードに対応させ、Metroで動作確認する。

進め方:
- `contextualStrings` に `['シャッター', '撮って', 'すごい', 'やばい', 'きた']` を渡す
- 実際の会話や車内環境で誤検知率・未検知率を計測する
- 感情語トリガー（「すごい」「やばい」「きた」）の誤検知が許容範囲かを判断する

確認すること:
- 複数ワードを渡した場合の認識精度
- 日常語の誤検知率が許容範囲か
- 感情語トリガーと明示的コマンドで処理を分けるべきか

#### ② フレーム抽出（既存 dev build で試験可能）

60秒クリップから1〜2秒に1枚フレームを抽出する手段を確認する。

進め方:
1. `expo-video-thumbnails` を使い、任意の動画ファイルで特定タイムスタンプのフレーム抽出を試す
2. 抽出速度・画質・任意タイムスタンプへの対応を確認する
3. 候補3枚の生成までの待ち時間が許容できるか計測する
4. `expo-video-thumbnails` でNGなら `ffmpeg-kit-react-native` を試す（この場合は再ビルド必要）

確認すること:
- `expo-video-thumbnails` で任意タイムスタンプの抽出が可能か
- `ffmpeg-kit-react-native` の導入コストとアプリサイズへの影響
- iOS / Android それぞれで処理速度に差がないか

#### ③ ローリングバッファ録画（再ビルド必要・最難関）

直近30秒を常時バッファリングする仕組みを確認する。このプロダクトの中核であり、技術的に最も難易度が高い。

進め方:
1. `expo-camera` でチャンク録画（5秒ずつ×6本を循環）を実装して試す
2. 継ぎ目の品質・メモリ使用量・発熱・バッテリー消費を実機で計測する
3. 問題があれば `react-native-vision-camera` を評価する
4. それでも難しい場合はネイティブモジュールの追加を検討する

確認すること:
- `expo-camera` の録画 API でローリングバッファが実現できるか
- チャンク録画の継ぎ目がフレーム抽出に影響しないか
- バッファ保持中の発熱・バッテリー消費が許容範囲か
- バッファ用一時ファイルサイズと端末ストレージへの影響
- `react-native-vision-camera` への移行が必要か

### P1: コア機能実装（技術検証後に着手）

技術検証の結果を踏まえて実装する。依存関係の順に列挙する。

1. **デフォルトカメラを内側カメラに変更**
   - 起動直後に内側カメラを立ち上げる。

2. **複数音声トリガー検知**
   - 「シャッター」「撮って」「すごい」「やばい」「きた」をトリガーとして扱う。
   - 技術検証①の結果を反映して実装する。

3. **ローリングバッファ録画**
   - アプリ起動中、直近30秒を常時バッファリングする。
   - 技術検証③で選定した方式で実装する。

4. **トリガー後録画継続とクリップ生成**
   - 音声トリガー検知後、30秒録画を継続する。
   - トリガー前30秒 + トリガー後30秒の合計60秒を一時クリップとして保存する。

5. **フレーム抽出**
   - 一時クリップから1〜2秒に1枚フレームを抽出する。
   - 技術検証②で選定した方式で実装する。

6. **簡易スコアリング**
   - 抽出フレームに対して以下を評価する:
     - ブレ（ラプラシアン分散など）
     - 明るさ
     - 顔の有無と大きさ
     - トリガー前後のタイミング分散
     - 類似フレームの除外
   - スコア上位3枚をベストショット候補とする。

7. **ベストショット候補3枚表示UI**
   - 候補3枚を並べて表示する。
   - ユーザーが保存する写真を選べるようにする。

8. **保存処理の刷新**
   - 旧方針（前後写真セット・合成写真）の保存処理を削除する。
   - 新方針（ベストショット候補 + ユーザー選択写真）の保存処理に置き換える。
   - DBスキーマをトリガー単位の管理に刷新する。

### P2: 整理・改善

1. **旧合成コードの削除**
   - `utils/composePhoto.ts`
   - `utils/detectFace.ts`
   - `features/photo-sets/diagonal-composition.ts`
   - `components/camera/CaptureSwitchingOverlay.tsx`
   - 合成関連UIコンポーネント全般

2. **アルバムUIのトリガー単位対応**
   - 現在は写真セット単位の表示。トリガー（撮影イベント）単位に刷新する。
   - ベストショット候補3枚の確認と保存写真の主表示を設計する。

3. **カメラUI整理**
   - 内側カメラデフォルト、バッファ録画中表示、音声検知状態表示、候補生成中表示を整理する。
   - 外側カメラへの切り替えボタン配置を見直す。

4. **一時クリップの削除タイミング設計**
   - ユーザーが保存写真を選択した後、一時クリップをいつ削除するか決める。

## 再ビルド判断

通常の JS / TS / UI 変更だけであれば development build の作り直しは不要。

以下は development build の作り直しが必要になる可能性がある。

- ローリングバッファ録画のためのネイティブモジュール追加
- フレーム抽出ライブラリの追加（ffmpeg-kit 等）
- `app.config.ts` の権限・plugin・background mode 変更
- `react-native-vision-camera` への移行
- 新しい Expo module または React Native native module の追加
