# プロダクト方針

## プロダクトの目標

LifeCube は、iOS / Android の両方で動作するインストール可能なモバイルアプリを目指す。

LifeCube が目指す顧客価値は、家族や仲間が一緒に過ごす時間の中で、自然な会話、笑顔、驚き、リアクションなど、後から見返したくなる感情の瞬間を、アプリを強く意識せずに残せることである。

写真を撮ること自体が目的ではない。
LifeCube が残したいのは、きれいな風景写真や記録写真そのものではなく、「その時、誰がどんな表情をしていたか」「どんな反応をしていたか」「どんな会話や空気感があったか」が思い出せる瞬間である。

LifeCube では、撮影の中心を内側カメラに置く。
家族や仲間の表情、会話中のリアクション、子どもの一言、笑い合う瞬間など、人の感情が表れる場面を中心に残す。

外側カメラは補助的な撮影手段として用意する。
景色、対象物、車窓、訪問先、出来事そのものを残したい場合には、ユーザーが外側カメラへ切り替えられるようにする。

LifeCube の中心体験は、ユーザーが撮影操作に集中することではなく、自然な会話や発話、感情が高まる言葉をきっかけに、その前後の時間から思い出として残すべき写真候補が自動で提示されることである。

## プロダクトコンセプト

LifeCube は、感情が動いた瞬間の前後から、残したい写真を自動で拾ってくれる、内カメラ中心の思い出カメラである。

従来のカメラでは、撮りたい瞬間ほど、手がふさがっていたり、会話に集中していたり、出来事に夢中になっていたりして、撮影できないことが多い。

また、動画を回し続ければ記録はできるが、後から長い動画を見返し、良い瞬間を探し、スクリーンショットを撮るのは手間が大きい。

LifeCube は、その課題に対して、音声トリガー、直近30秒の一時録画、トリガー後30秒の録画継続、ベストショット候補の自動抽出を組み合わせる。

ユーザーが「撮る」ことを意識しすぎなくても、感情が動いた前後60秒の中から、残したい写真候補を3枚提示する体験を提供する。

特に重視する価値は以下である。

* 撮影操作よりも、その場の会話や体験に集中できること
* 風景だけでなく、人の表情や反応が残ること
* 「今の表情、撮れていたらよかった」と後悔する瞬間を減らすこと
* 長い動画を見返さなくても、残す価値のある写真候補が見つかること
* ユーザーが保存する写真を自分で選べること
* 後から家族や仲間と見返したときに、会話や感情がよみがえること

## 想定する利用シーン

LifeCube の初期利用シーンは、家族や仲間が移動中または外出先で一緒に過ごす場面を中心にする。

特に、以下のような状況を想定する。

* 車での家族旅行やドライブ
* 子どもとのお出かけ
* 車内で子どもが面白いことを言った瞬間
* 家族や仲間が景色や出来事に反応した瞬間
* 会話が盛り上がった瞬間
* みんなで笑った瞬間
* 誰かが驚いた、喜んだ、照れた、得意げになった瞬間
* 「すごい」「やばい」「きた」など、感情が上がる言葉が自然に出た瞬間
* 釣り、スポーツ、発表、遊びなど、本人や周囲が出来事に集中していて撮影しにくい瞬間

初期プロダクトでは、家族の車移動を主要ユースケースとする。
ただし、将来的には「撮りたい瞬間ほど手がふさがっている」「感情が動いた瞬間を後から見たい」という共通課題を持つ文脈に拡張できる可能性を持たせる。

## MVP のコア体験

MVP における LifeCube のコア体験は、以下の流れで構成する。

1. 内カメラをデフォルトで起動する
2. 直近30秒を一時録画する
3. 「シャッター」「撮って」「すごい」「やばい」「きた」を検知する
4. トリガー後30秒まで録画を継続する
5. 合計60秒の一時クリップを作成する
6. その中からフレームを抽出する
7. ブレ・明るさ・顔の有無などで簡易スコアリングする
8. ベストショット候補を3枚表示する
9. ユーザーが保存する写真を選ぶ

MVP の目的は、ユーザーが撮影操作をしなくても、感情が動いた瞬間の前後から「残したい」と思える写真候補が提示される体験を検証することである。

MVP では、完璧なAI判定や高度な表情理解を目指さない。
まずは、長い動画を見返さなくても、保存したい写真候補が3枚提示されることに価値があるかを検証する。

## 撮影体験の方針

LifeCube では、撮影を「明示的にカメラを構える行為」ではなく、「自然な発話や会話の流れの中で起きる行為」として設計する。

MVP では、以下の撮影体験を中核とする。

* アプリ起動直後の初期画面はカメラ画面にする
* デフォルトカメラは内側カメラにする
* アプリ起動中は、直近30秒を一時録画し続ける
* 「シャッター」「撮って」「すごい」「やばい」「きた」の音声トリガーに反応する
* 音声トリガーを検知したら、トリガー後30秒まで録画を継続する
* トリガー前30秒からトリガー後30秒までの合計60秒を一時クリップとして扱う
* 一時クリップから複数フレームを抽出する
* ブレ・明るさ・顔の有無などの簡易基準でスコアリングする
* ベストショット候補を3枚表示する
* ユーザーが保存したい写真を選択する
* 保存された写真はアプリ内アルバムに表示する
* 必要に応じて、ユーザーは外側カメラへ切り替えられる

現時点では、前後カメラの同時撮影または順次撮影は行わない。
また、外側写真と内側写真の合成機能も MVP からは除外する。

LifeCube における撮影成果物は、原則として「自動で選ばれた1枚」ではなく、「ユーザーに提示されるベストショット候補」である。
最終的に何を残すかは、ユーザーが選べるようにする。

## 音声トリガーの方針

MVP では、以下の音声トリガーを対象とする。

* シャッター
* 撮って
* すごい
* やばい
* きた

「シャッター」「撮って」は、ユーザーが撮影意思を持って発する明示的なコマンドとして扱う。
「すごい」「やばい」「きた」は、感情が上がったときに自然に出る言葉として扱う。

この2種類のトリガーは、UX上の意味が異なる。

* 明示的コマンド：撮りたい意思を直接反映する
* 感情語トリガー：撮りたいと意識する前の感情の高まりを拾う

LifeCube が特に重視するのは、後者の感情語トリガーである。
感情が動いた言葉をきっかけに、その前後の時間から残したい写真候補が提示されることが、LifeCube の独自価値である。

ただし、MVP ではトリガー認識の精度を完璧にすることは目的としない。
誤検知や未検知が一定程度起きる前提で、ユーザーが体験価値を感じるかを検証する。

## 一時録画とクリップ生成の方針

MVP では、アプリ起動中に直近30秒を一時録画する。

音声トリガーを検知した場合、そこからさらに30秒録画を継続し、トリガー前30秒からトリガー後30秒までの合計60秒を一時クリップとして扱う。

この一時クリップは、ベストショット候補を生成するための材料であり、長期保存を前提としない。
ユーザーに提示する最終成果物は、原則として一時クリップから抽出された写真候補である。

MVP では、元動画を恒久保存することを前提にしない。
ただし、検証やデバッグ、ユーザーが候補写真を選び直すために、短時間またはセッション中のみ一時的に保持することは許容する。

## ベストショット候補生成の方針

LifeCube は、MVP で高度なAIによる完璧なベストショット判定を目指さない。

MVP では、以下のような簡易基準で候補画像を選ぶ。

* ブレが少ない
* 明るさが極端に悪くない
* 顔が写っている
* 顔が大きく写りすぎていない、または小さすぎない
* 構図が大きく崩れていない
* トリガー前後のタイミングに分散している
* 3枚が似た画像になりすぎない

MVP でのベストショット生成は、「AIが完璧な1枚を決める」体験ではなく、「長い動画を見返さずに、保存候補を3枚に絞ってくれる」体験である。

ユーザーは提示された3枚の中から、保存したい写真を選ぶ。
3枚すべて保存できる設計も検討するが、基本体験としては「候補提示」と「ユーザー選択」を重視する。

## 外側カメラの方針

MVP のデフォルトは内側カメラとする。

LifeCube が最も重視するのは、家族や仲間の表情、反応、会話の空気感である。
そのため、起動時には内側カメラを立ち上げる。

ただし、ユーザーが景色、対象物、車窓、訪問先、出来事そのものを撮影したい場合に備え、外側カメラへの切り替え機能を用意する。

外側カメラは補助的な撮影手段であり、MVP の中心価値ではない。
外側カメラでも同様に、音声トリガー、一時録画、ベストショット候補生成が使えるかは、技術実装の状況に応じて判断する。

## 保存方針

LifeCube では、ユーザーが選択した写真をアプリ内アルバムに保存する。

MVP では、1回のトリガーにつき以下を保存対象とする。

* ベストショット候補3枚
* ユーザーが選択した保存写真
* 必要に応じて、候補生成に使った一時クリップの参照情報

端末の写真アプリには、ユーザーが保存または共有を選択した写真を保存する。

MVP では、アプリ内アルバムを主たる保存場所とし、端末写真アプリへの保存はユーザーの操作に基づく形を基本とする。

元動画は、原則として長期保存しない。
LifeCube は長時間録画アプリではなく、感情が動いた前後から残したい写真を抽出するアプリである。

## アルバム体験

LifeCube のアルバムは、単なる画像一覧ではなく、感情が動いた瞬間を見返す場所とする。

MVP では、以下の体験を目指す。

* アプリで保存した写真を日付ごとに表示する
* 内側カメラで撮影された写真を中心に見返せる
* 音声トリガーごとに生成されたベストショット候補を確認できる
* ユーザーが保存した写真を主表示する
* 必要に応じて、候補3枚を見返せる
* 外側カメラで撮影した写真も同じアルバム内に表示する
* 撮影した写真を端末の写真アプリや SNS、メッセージアプリに共有できる
* 後から見返したときに、その場の会話や感情が思い出せる

将来的には、以下の拡張を検討する。

* 家族旅行やイベント単位でのグルーピング
* ベストショット候補の自動整理
* 音声トリガーごとの分類
* 位置情報や移動ルートとの連携
* 家族やメンバー間での共有アルバム
* クラウド同期
* 短いハイライト動画の保存
* 候補写真の手動再抽出

## 開発方針

LifeCube は、Web だけでなく、実際に端末へインストールして動作するモバイルアプリとして開発する。

開発基盤は以下を前提とする。

* Expo / React Native を利用する
* アプリコードは TypeScript を前提にする
* iOS / Android の両対応を目指す
* カスタムネイティブコードよりも、まずはライブラリや Expo modules の利用を優先する
* ただし、カメラ、音声検知、ローリングバッファ録画、フレーム抽出など、体験価値に直結する部分では、必要に応じてネイティブ実装も検討する
* Web 対応は、当面は開発確認用と位置づける
* スマホ向けカメラ体験の検証を優先し、iPad 横向き最適化は後回しにする

MVP では、技術的な完成度よりも、以下の体験が成立することを優先する。

* 内カメラがデフォルトで起動する
* 直近30秒を一時録画できる
* 複数の音声トリガーを検知できる
* トリガー後30秒まで録画を継続できる
* 合計60秒の一時クリップを作成できる
* 一時クリップからフレームを抽出できる
* 簡易スコアリングで候補画像を選べる
* ベストショット候補を3枚表示できる
* ユーザーが保存する写真を選べる
* アプリ内で思い出として見返せる

## MVP の中核機能

MVP の中核機能は以下とする。

* カメラ画面
* デフォルト内側カメラ
* 外側カメラへの切り替え
* 直近30秒の一時録画
* 複数音声トリガー検知
* トリガー後30秒の録画継続
* 60秒一時クリップ生成
* フレーム抽出
* 簡易スコアリング
* ベストショット候補3枚表示
* ユーザーによる保存写真選択
* 撮影結果プレビュー
* アプリ内アルバム
* 端末写真アプリへの保存
* SNS / メッセージアプリへの共有導線
* 簡素なガイド画面
* ホーム画面
* 設定画面
* 課金設定の入口

下部タブは、以下で構成する。

* カメラ
* アルバム
* ガイド
* ホーム

起動直後はカメラ画面を表示する。
カメラ画面では、内側カメラをデフォルトで起動する。

## UI/UX 方針

LifeCube の UI/UX は、撮影操作を目立たせすぎず、体験や会話の邪魔をしないことを重視する。

基本方針は以下である。

* 起動後すぐに使える
* デフォルトで内側カメラが起動する
* 一時録画中であることが分かる
* 音声検知が有効であることが分かる
* 検知対象の音声トリガーが分かる
* トリガー検知時に、録画継続中であることが分かる
* ベストショット候補生成中であることが分かる
* 候補3枚を簡単に比較できる
* 保存する写真を迷わず選べる
* 内側カメラと外側カメラの切り替えが簡単である
* 撮影成功・失敗が明確に分かる
* 保存された思い出を簡単に見返せる
* 家族や一般ユーザーでも迷わない
* 車内利用を想定し、細かすぎる操作を避ける
* アプリを使っていることよりも、体験そのものが主役になるようにする

UI/UX の詳細は `ui-ux/` 配下で管理する。

## 検証方針

LifeCube の検証では、技術的に撮影・抽出できるかだけでなく、提示された候補写真がユーザーにとって思い出として価値を持つかを重視する。

特に検証すべき問いは以下である。

* ユーザーは内カメラをデフォルトにする体験を自然だと感じるか
* 車内や外出先でスマホを設置することに抵抗がないか
* 内カメラで家族や仲間の表情を残す価値を感じるか
* 「シャッター」「撮って」「すごい」「やばい」「きた」は自然なトリガーとして機能するか
* 音声トリガーが会話や体験を邪魔しないか
* トリガー前30秒から後30秒までを対象にする設計は適切か
* ベストショット候補3枚の中に、ユーザーが残したいと思う写真が含まれるか
* 動画を見返して自分で探すより便利か
* ブレ・明るさ・顔の有無などの簡易スコアリングで十分な候補が出るか
* 3枚という候補数は適切か
* ユーザーは候補から写真を選ぶ体験を面倒だと感じないか
* 撮った写真を家族や友人と見返したくなるか
* SNS やメッセージで共有したくなるか
* 「撮りたい瞬間ほど撮れない」という課題に対して、LifeCube が有効か

## 今後明確にすること

今後、以下を明確にする。

* 最初に狙う対象ユーザー
* 家族車移動を主軸にするか、より広い Performance Memory 文脈に広げるか
* 車内でのスマホ設置方法
* 内カメラで家族や仲間の表情が撮れる設置位置
* どのスマホホルダーや設置条件であれば安定して使えるか
* 外カメラ切り替えがどの程度使われるか
* 音声トリガーの最適な言葉
* トリガー前後30秒という時間設定が適切か
* 候補写真を3枚にするのが適切か
* 一時クリップをどの時点で削除するか
* 元動画を保存するオプションを用意するか
* フレーム抽出の間隔
* 簡易スコアリングの基準
* 顔検出や表情推定をどこまで使うか
* SNS 投稿まで含めた具体的な利用シーン
* 初回リリースでクラウド同期が必要か
* Web 対応を開発確認用に留めるか、正式な対応対象にするか
* 写真アプリ側で削除、編集、移動された画像をどう扱うか
* iPad への最適化範囲
* 課金する場合の価値単位
* 家族以外のユースケースに拡張するタイミング

## 現時点でやらないこと

現時点では、以下はやらない。

* 前後カメラの同時撮影
* 前後カメラの順次撮影
* 外側写真と内側写真の合成
* 合成プレビュー
* 合成後写真の保存
* 外側写真・内側写真・合成写真の3枚セット保存
* 高度なAIによる完璧なベストショット判定
* 高精度な表情認識を前提とした体験設計
* 長時間動画を恒久保存する録画アプリ化
* 複雑な動画編集機能
* 写真加工アプリとしての多機能化
* デプロイや審査要件が明確になる前に、本番ストア公開を前提に最適化しすぎること
* データモデルや同期要件が固まる前に、バックエンド構成を固定すること
* スマホ向けカメラ体験が固まる前に、iPad 横向きの画面を作り込みすぎること
* 釣り、スポーツ、発表などの派生ユースケースに最初から最適化しすぎること
* SNS 投稿機能をプロダクトの主目的にしすぎること
* クラウド同期や家族共有など、体験価値の検証前に重い機能を先行実装しすぎること
* カメラ機能そのものの多機能化を目的化すること

## プロダクト判断の原則

LifeCube の開発判断では、以下を優先する。

1. 撮影操作より、体験や会話への集中を優先する
2. 風景よりも、人の表情・反応・感情が残ることを重視する
3. 長い記録より、後から見返したくなる瞬間を重視する
4. 動画を残すことより、写真として見返しやすい成果物を重視する
5. 技術的に面白い機能より、ユーザーが残したいと思う候補写真を優先する
6. 完璧な自動判定より、ユーザーが選べる候補提示を優先する
7. 写真・動画・AIの機能追加は、思い出を自然に残す体験に資する場合のみ行う
8. アプリの存在感を強めるより、自然なコミュニケーションの中に溶け込むことを重視する
9. 外側カメラは補助機能とし、初期体験では内側カメラによる感情の記録を優先する
10. MVP では高度なAIではなく、簡易スコアリングでも価値が成立するかを検証する

LifeCube は、写真を撮るためのアプリではなく、感情が動いた前後から、残したい一瞬を自然に見つけて思い出として残すアプリである。
