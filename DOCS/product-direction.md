# プロダクト方針

## プロダクトの目標

LifeCube は、iOS / Android の両方で動作するインストール可能なモバイルアプリを目指します。

LifeCube が目指す顧客価値は、家族が集まり、会話し、お互いに反応し合う時間の中で、家族で楽しみ、一体感を持てる思い出を自然に残せることです。

写真を撮ること自体が目的ではありません。アプリを強く意識せず、自然な会話や発話の流れの中で撮影が起き、コミュニケーションに集中したまま思い出が残る体験を目指します。

外側カメラと内側カメラをセットで残す理由は、風景や出来事だけでなく、それを見ている家族自身の表情や反応も一緒に記録するためです。どこに行ったかだけでなく、その時に誰がどう感じ、どう楽しんでいたかを後から振り返れることを重視します。

プロダクト体験の中心は、音声検知で前後カメラを連続撮影し、出来事と反応を1セットの写真として扱うことです。設定により、背面カメラのみで1枚写真を残すモードも用意します。

## 現在の方向性

- Web だけでなく、実際に端末へインストールして動作するアプリとして作ります。
- 開発基盤は Expo / React Native を使います。
- アプリコードは TypeScript を前提にします。
- カスタムネイティブコードよりも、まずはライブラリや Expo modules の利用を優先します。
- 起動直後の初期画面はカメラ画面にします。
- MVP の中核は、カメラ、音声検知撮影、合成プレビュー、アプリ内アルバムです。
- カメラは当面「シャッター」という音声に反応して、外側カメラ、内側カメラの順に撮影します。将来的に他の音声トリガーを追加する可能性があります。
- 背面カメラのみモードでは、前面カメラへ切り替えず背面写真1枚を保存します。
- 撮影後は、デフォルトで円形くり抜きの合成プレビューを表示します。
- アルバムでは、このアプリで撮影した写真セットまたは背面写真を日付ごとに表示します。
- LifeCube 内アルバム用には、前後カメラ撮影では外側写真、内側写真、合成後写真の3枚を保存し、背面カメラのみ撮影では背面写真1枚を保存します。
- 端末の写真アプリには、合成後写真または背面写真の成果物画像だけを保存します。
- 下部タブは、カメラ、アルバム、ガイド、ホームで構成します。
- ガイドには、写真撮影の仕方を確認できる簡素な案内を置きます。
- ホームには説明、設定、課金設定の入口を置きます。
- MVP では Instagram 共有導線を入れます。
- UI/UX の詳細は `ui-ux/` 配下で管理します。

## 現時点でやらないこと

- デプロイや審査要件が明確になる前に、本番ストア公開を前提に最適化しすぎない。
- データモデルや同期要件が固まる前に、バックエンド構成を固定しない。
- スマホ向けカメラ体験が固まる前に、iPad 横向きの画面を作り込みすぎない。
