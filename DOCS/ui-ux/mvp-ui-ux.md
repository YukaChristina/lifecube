# MVP UI/UX 方針

## MVP の中心体験

LifeCube は、何かを撮りたいと思った瞬間に開くアプリです。

そのため、アプリ起動時の最初の画面はカメラ画面にします。ユーザーがホーム画面を経由してから撮影を始める構成にはしません。

ただし、最終的な目的は写真を撮ること自体ではありません。家族の会話や反応の流れを妨げず、コミュニケーションに集中したまま、出来事と撮影者側の表情をセットで残すことを重視します。

MVP で必要な主要機能は以下です。

- カメラ機能
- 音声検知による撮影
- 外側カメラと内側カメラの連続撮影
- 撮影後の合成プレビュー
- アプリで撮影した写真セットだけを扱うアルバム
- 撮影方法を確認できるガイド
- 合成パターンの選択と保存
- Instagram への共有

ホーム画面は、アプリ説明、合成パターン設定、課金設定の入口として使います。設定画面を独立タブにはせず、ホーム配下で扱います。課金設定は未実装でも入口を表示し、「準備中」として扱います。

## 対象端末

- iOS と Android の両方を対象にする。
- スマホファーストで設計する。
- スマホの横向き利用は直近対応に含める。
- iPad のような大きめ端末の最適化は将来対応として検討する。
- PC での利用は想定しない。

将来的な iPad 横向きでは、右側に直近写真やアルバム導線を出す 2 ペイン構成が候補です。ただし、MVP 初期では未決定事項として扱います。

## ナビゲーション

画面下部にタブを置きます。

タブ:

- カメラ
- アルバム
- ガイド
- ホーム

タブ表記は日本語の `カメラ / アルバム / ガイド / ホーム` にします。

起動直後は常にカメラタブを開きます。

初期実装では、Expo Router の `app/(tabs)/index.tsx` をカメラ画面にします。アルバムは `app/(tabs)/gallery.tsx`、ガイドは `app/(tabs)/guide.tsx`、ホームは `app/(tabs)/home.tsx` に接続します。`explore` はタブにも画面にも残しません。

## 初回権限許可

カメラ、マイク、音声認識、写真ライブラリの初回許可では、OS標準の権限ダイアログが表示されます。

アプリ側で制御できるもの:

- どのタイミングで許可を求めるか。
- OSダイアログを出す前に、アプリ内で事前説明を表示するか。
- iOS の `Info.plist` に入れる許可理由の文言。
- 許可されなかった場合のアプリ内表示。

アプリ側で自由に変えられないもの:

- OS標準ダイアログ自体のレイアウト。
- OS標準ダイアログのボタン構成。
- Android / iOS 固有の許可UIの細部。

MVP では、基本的に OS 標準の権限ダイアログを使います。初回権限未許可の状態でも、起動直後はカメラ画面風の背景を表示し、許可が必要であることが分かる状態にします。

アプリ起動直後に権限状態やカメラ起動状態を読み込んでいる短い間は、権限案内を出しません。カメラ画面風の静かな背景だけを表示し、実際に未許可または拒否状態だと判定できた場合だけ権限案内を表示します。

権限が拒否された場合:

- アプリの中核機能は使えないため、カメラ画面風の背景上に、許可が必要であることを表示する。
- 次回以降の起動時にも、再度許可を試せる導線を出す。
- OSの仕様上、通常の許可ダイアログを再表示できない場合は、設定アプリを開く導線を出す。
- 一度拒否したユーザーが、後から許可へ変更する方法が分からなくなる状態を避ける。

事前説明画面を必ず出すかどうかは、初期実装の結果を見て調整します。

## カメラ画面

撮影中は、画面全体にカメラプレビューを表示します。

前後カメラの同時プレビューが難しい場合は、外側カメラだけを表示して問題ありません。

撮影モード:

- 基本は、外側カメラと内側カメラを連続撮影する。
- 設定により、背面カメラのみで撮影するモードも用意する。
- 背面カメラのみモードの設定名は未決定とする。
- 背面カメラのみの場合、合成写真は作らず、背面写真1枚を LifeCube アルバムと端末の写真アプリの両方に保存する。

撮影トリガー:

- 「シャッター」という音声に反応して撮影する。
- 画面上のシャッターボタンでも撮影できるようにする。
- 将来的に「シャッター」以外の音声トリガーを追加する可能性がある。
- 「シャッター」を検知できなかった場合は、基本的に何も返さない。

音声認識状態の表示:

- 認識中、待機中の表示は控えめにする。
- カメラ体験への集中を優先する。
- 意味が伝わりにくい小さなドット表示は使わない。
- 代わりに、`「シャッター」と言うと撮影します` のような短い案内文を控えめに表示する。
- 案内文は仮の文言として扱う。将来的に「シャッター」以外の音声トリガーを追加する可能性がある。
- 実際に音声認識エラーが起きた場合は、再撮影や再試行が分かる程度にやや強調する。
- 真っ赤な警告UIは使わず、パステルの範囲で表現する。

撮影順:

1. 外側カメラで撮影する。
2. 内側カメラに切り替える。
3. 内側カメラの準備完了後に撮影する。
4. 合成プレビューを表示する。

現時点では前後撮影にタイムラグがあるため、切り替え中に注意メッセージを表示します。固定の `500ms` 待ちは、`onCameraReady` や実機検証結果に応じて短縮します。

表示文言:

```text
撮影切り替え中です
カメラを動かさないでください
```

カメラや写真に重なるメッセージは、全体共通で透明度を高めにします。メッセージの読みやすさは確保しますが、カメラ映像や写真が完全に見えなくなる領域は作りません。

## 撮影後プレビュー

撮影後は、最初から合成後プレビューを表示します。

デフォルトの合成パターンは「円形くりぬき」です。設定でデフォルト合成パターンを変更できるようにします。

撮影後の挙動:

- 合成プレビューを4秒表示する。
- 背景部分のタップ、または4秒経過でカメラ画面に戻る。
- 4秒後に戻ることが分かるように、控えめな進捗バーを表示する。
- 進捗バーは、薄いトラックの上を少し濃いバーが左から右へ伸びる表示にする。
- 進捗バーの高さは8pxにする。
- プレビュー上部に「画面をタップでカメラへ戻る」を表示する。
- この案内はボタン風にせず、上部の薄い帯と下線で、画面全体にかかる意味を伝える。
- 外側写真、内側写真、合成後写真の3枚をアプリ内保存領域へ自動保存する。
- 前後カメラ撮影では合成後写真、背面カメラのみ撮影では背面写真を端末の写真アプリにも自動保存する。
- 写真セット情報は `expo-sqlite` のローカルDBへ保存する。
- 保存完了表示は出さない。
- 合成プレビュー上に「Instagramで共有」導線を出す。
- 「Instagramで共有」は1行表示にし、押した場合はOS共有シートへ移行する。
- 「削除する」導線を出す。確認ダイアログは出さず、即時にカメラ画面へ戻る。
- 「Instagramで共有」と「削除する」は、誤タップを避けるために十分に離して配置する。
- 背景タップ領域と、共有・削除ボタンのタップ領域は明確に分ける。
- 保存ボタンや撮り直しボタンは表示しない。

写真セットの最小DB項目:

```text
id
createdAt
captureMode
orientation
backLocalUri
frontLocalUri
composedLocalUri
composedAssetId
pattern
composedWidth
composedHeight
frontImageFocusX
frontImageFocusY
frontImageScale
deletedAt
```

アルバムの日付順や日付グルーピングでは `createdAt` を使います。`id` には時刻由来の文字列を含めますが、並び替えの正本にはしません。

`captureMode` は `dual` または `backOnly`、`orientation` は `portrait` または `landscape` とします。背面カメラのみ撮影では `frontLocalUri` と `pattern` と内側写真フォーカス項目を `null` にします。前後カメラ撮影では、内側写真フォーカス項目のデフォルトを `0.5 / 0.5 / 1.0` とし、将来の顔検出で置き換えられるようにします。

撮影後プレビューの「削除する」は、保存済みの場合はDBの `deletedAt` を設定し、アプリ内保存の写真セットを削除します。端末の写真アプリ側に保存済みの合成後写真は、OS確認ダイアログが絡むためMVP初期では削除しません。

## アルバム画面

アルバムには、このアプリで撮影した写真セットだけを表示します。

通常のカメラアプリで撮った写真は、LifeCube のアルバムには混ぜません。

一覧表示:

- 日付ごとに写真セットを並べる。
- 日付順と日付グルーピングは、DBの `createdAt` を使う。
- 日付見出しは `2026.05.06 Wed` のように、年月日と英語短縮曜日で表示する。
- 一覧には成果物画像だけを表示する。
- 縦向き写真と横向き写真の混在表示方式は、4列ベースの Mosaic / Quilted grid とする。
- 縦長写真は `1列 x 2行`、横長写真は `2列 x 1行`、必要に応じて小さく見せる写真は `1列 x 1行` として扱う。
- サムネイルは一覧では見栄え優先で `cover` 表示にする。
- 初期実装では追加ライブラリを入れず、`orientation`、`composedWidth`、`composedHeight` を使った配置ロジックを自前で実装する。
- 配置は時系列順を優先し、4列の仮想グリッドを上から順に埋める。
- 後続写真で過去行の空きを無理に埋め戻すと時系列が分かりにくくなるため、初期実装では行の流れを優先する。
- 例: 縦長写真が3枚続いた後に横長写真が1枚来た場合、縦長3枚は先頭2行の3列分を使う。横長写真は残り1列に入らないため、次の空き行に `2列 x 1行` で配置する。完全な面積効率より、時系列の読みやすさを優先する。
- 時刻表示は必須ではない。
- 外側写真、内側写真、合成後写真を同じ階層に並べない。
- 写真がまだない場合は「まだ写真がありません」と表示する。
- 合成後写真が削除されている写真セットは、アルバムに表示しない。
- 合成後写真が残っていれば、外側写真または内側写真が欠けていても一覧には表示する。
- 外側写真または内側写真が欠けている場合、オリジナル表示では欠けている写真を表示できない状態として扱う。
- アプリ内で写真セットを削除する場合は、`deletedAt` を設定し、アプリ内保存の外側写真、内側写真、合成後写真をまとめて削除する。

詳細表示:

- 写真セットを開くと、合成後写真を大きく表示する。
- 詳細画面では、保存済みの成果物画像を大きく表示する。
- 合成後写真は `contain` 表示とし、写真全体が見えることを優先する。
- 前後カメラ撮影では、詳細画面から合成パターンを切り替えられる。
- 背面カメラのみ撮影では、合成パターン切り替えを表示しない。
- 左右スワイプでの合成パターン切り替えは未実装とする。
- 「オリジナルを見る」ボタンを、合成写真にやや重なる形で薄く表示する。
- 「オリジナルを見る」から、元の外側写真と内側写真を表示する。背面カメラのみ撮影では背面写真だけを表示する。
- オリジナル表示では、外側写真を上、内側写真を下に並べる。
- 合成パターンを切り替えた場合は、選択した合成パターンと再生成した成果物画像を保存する。
- Instagram 共有導線を置き、共有対象は成果物画像だけにする。
- 「削除する」導線を置く。
- 詳細画面での削除は確認ダイアログを出す。
- 削除確定時は、DBに `deletedAt` を設定し、アプリ内保存の外側写真、内側写真、合成後写真を削除してからアルバム一覧へ戻る。
- 端末の写真アプリ側に保存された合成後写真は、MVP初期では削除しない。

## ガイド画面

ガイド画面は、撮影方法を確認するための補助画面です。

初期実装では簡素なたたき台にします。内容は後から整理します。

最初に置く候補:

- 「シャッター」と言うと撮影できること。
- 外側カメラと内側カメラを連続撮影すること。
- 撮影後は4秒間プレビューが表示されること。
- アルバムから撮影済み写真を見返せること。
- 成果物画像は端末の写真アプリにも保存されること。
- 完全に削除したい場合は、LifeCube内アルバムと端末の写真アプリの両方を確認する必要があること。

ガイドは、撮影体験を邪魔しないための補助情報として扱います。初回起動時に強制表示するチュートリアルにはしません。

## 合成パターン

MVP では 3 種類の合成パターンを用意します。

合成画像出力は、スマホ縦向きでは `1080 x 1920` の9:16、スマホ横向きでは `1920 x 1080` の16:9を基本にします。カメラ解像度や元写真比率を保った高画質出力は将来検討とします。

### 1. ゆるやかな斜めカット

初期実装済みの合成パターンの1つです。

外側写真と内側写真を、右上から左下へ抜ける3次ベジェ曲線の境界で組み合わせます。比率は視覚的に美しく見えることを重視し、境界線は写真を邪魔しすぎない太さにします。

ホームの合成パターン選択UIでも、斜めカットのサンプルは同じ曲線分割の見た目にします。

### 2. 円形くりぬき

デフォルトの合成パターンです。

外側カメラ写真を背景として大きく表示し、内側カメラ写真を円形に切り抜いて重ねます。

基本方針:

- 外側写真をメインにする。
- 内側写真を円形に切り抜く。
- 内側写真は顔が写っている部分を中心に切り抜く。
- 配置は背景写真の右側を候補にする。

顔検出や自動トリミングが難しい場合、MVP では中央寄せの円形切り抜きから始めます。

### 3. 左右分割

外側写真と内側写真を左右に分割して表示します。

単純に写真の右半分・左半分を切り出すのではなく、それぞれの写真の中央部分が見えるように配置します。

境界は明確に分かる必要があります。枠線の太さや色は、写真を見ながら調整します。候補色は、自然界に少ないパステルピンク、パステルブルー、ミントなどです。

MVP では、合成パターン名をUI上に表示しません。ユーザーは見た目だけで、斜めカット、円形くりぬき、左右分割の3パターンを選びます。

## 合成境界線の暫定指定

初期実装では以下の値を使います。写真との相性を見て必要に応じて修正します。

- 斜めカット境界線: `#F3B8C8`、4px、opacity 0.82
- 円形くりぬき枠線: `#C8DFF2`、4px、opacity 0.86
- 左右分割境界線: `#C7E6DC`、6px、opacity 0.88

## 設定で持ちたい項目

ホーム配下の設定に置く項目:

- 撮影後プレビューのデフォルト合成パターン
- 撮影モード。前後カメラ撮影または背面カメラのみ撮影
- 音声トリガーの有効 / 無効
- 課金設定

ホームに最初から表示する項目:

- アプリ説明
- 合成パターン設定
- 課金設定入口

課金設定入口:

- MVPでは未実装でも表示する。
- 表示文言は「準備中」とする。

デフォルト合成パターンの選択UI:

- ラジオボタン自体は表示しない。
- 3種類の合成サンプル画像を並べる。
- 3種類の合成パターンをタップして選択できるようにする。
- 初期値は円形くりぬきにする。
- 選択中のサンプルは、枠線や淡い背景で分かるようにする。
- 長い日本語説明ではなく、見た目で選べるUIにする。
- 合成パターン名は表示しない。

将来的な候補:

- 撮影時の注意メッセージの表示有無
- 合成パターンごとの境界線カラー

## デザイン方向性

世界観は、静かでかわいいが幼すぎない方向に寄せます。

候補ニュアンス:

- Soft Editorial: 雑誌の写真レイアウトのように、余白と細い線で写真を引き立てる。
- Quiet Pastel Camera: 淡い色を少量だけ使う、落ち着いたカメラアプリ。

UIは写真を主役にします。枠線、メッセージ、タブ、ボタンは控えめにし、必要な瞬間だけ少し印象に残る色を使います。

写真に絡むUIと撮影中の注意メッセージにはパステルカラーを使います。アルバムとホームは、パステルだけに寄せすぎず、大人びた静かな質感にします。

アルバムとホームの仮デザイントーンは、`#F8FBFA` のごく薄いミント白を背景にし、`#44504D` の柔らかい文字色、`#F3B8C8` と `#C7E6DC` の控えめなアクセントで統一します。

UI文言は当面すべて日本語固定にします。
