# UIデザイン方針

## 位置づけ

この文書は、LifeCube のUIデザイン上の判断をまとめます。

Expo スターター由来の UI と開発用の音声テスト画面は、プロダクト画面から削除します。MVP ではカメラ、アルバム、ガイド、ホームに整理します。

## デザイン方向性

候補キーワード:

- Quiet Pastel
- Soft Editorial

静かでかわいいが、幼すぎない。SNS に投稿しても大人が恥ずかしくない温度感を目指します。

避ける方向:

- SF感
- 儀式感
- 幼いかわいさ
- 強い警告色
- 写真を覆い隠すUI

写真に絡むUI、撮影中メッセージ、合成境界線にはパステルカラーを使います。アルバムやホームは、パステルだけに寄せすぎず、もう少し大人びた静かな質感にします。

## 当面の UI 原則

- モバイルファーストで設計します。
- 主要操作は、可能な範囲で片手でも届きやすくします。
- ネイティブアプリらしい自然な操作感と、予測しやすいナビゲーションを優先します。
- プロダクトの個性が明確になるまでは、装飾的な UI を増やしすぎません。
- カメラ、マイク、音声認識、メディアアクセスでは、権限・読み込み・エラー状態を明確に設計します。
- カメラ映像や写真に重なるUIは、透明度を高めにし、完全に見えなくなる領域を作りません。
- 音声認識中や待機中の表示は控えめにします。
- 実際の失敗状態はやや強調しますが、真っ赤な警告のような世界観を壊す表現は使いません。

## UIライブラリ方針

現時点では、NativeWind、Tamagui、React Native Paper、Gluestack UI などの大きなUIライブラリは導入しません。

理由:

- LifeCube はカメラ画面と写真体験が主役であり、フォームや業務画面中心のアプリではない。
- 外部UIライブラリの見た目に引っ張られると、Quiet Pastel / Soft Editorial の方向性を保ちにくい。
- MVP初期では、実機で写真・カメラ・重ねUIを見ながら微調整する必要がある。
- まずは既存の React Native `StyleSheet` と小さな共通コンポーネントで十分進められる。

当面の方針:

- `StyleSheet.create()` を基本にする。
- 色、透明度、枠線、余白などは、必要に応じて `constants/` にトークン化する。
- 再利用されるUIは `components/` に小さく切り出す。
- UIライブラリ導入は、画面数や共通部品が増えてから再検討する。

将来候補:

- NativeWind: Tailwind風の書き方が有効になった場合に検討する。
- Tamagui: デザインシステムを強く作る段階で検討する。
- React Native Paper: Material Design寄りでよい画面が増えた場合に検討する。
- Restyle: テーマと型安全なスタイル管理を優先したい場合に検討する。

## 暫定カラーと線

アルバムとホームの仮トーンは、Quiet Pastel のミント白ベースにします。写真を邪魔しない程度に、ごく薄い背景色と柔らかい文字色で統一します。

```text
background: #F8FBFA
surface:    #FFF9FB
primary:    #F3B8C8
accent:     #C7E6DC
text:       #44504D
subtext:    #6F7976
line:       #DDEDEA
```

アルバムとホームの共通ルール:

- 画面背景は `#F8FBFA` にする。
- 画面見出しは左余白20、上余白は safe area + 18 を基本にする。
- 画面見出しは28px、fontWeight 700、`#44504D` にする。
- セクション見出しは15px、fontWeight 800、`#44504D` にする。
- 本文は14px、lineHeight 22、`#6F7976` にする。
- 線や枠は `#DDEDEA` を基本にする。
- 写真や合成パターンに関わるアクセントとして `#F3B8C8` と `#C7E6DC` を使う。

合成境界線と撮影中UIは、以下を初期値として実装します。写真との相性を見て後から調整します。

- 合成画像出力: 縦向きは `1080 x 1920`、9:16。横向きは `1920 x 1080`、16:9。将来的には元写真の比率やカメラ解像度に応じた高画質出力を検討する。
- アルバムサムネイル: 4列ベースの Mosaic / Quilted grid とする。縦長は `1列 x 2行`、横長は `2列 x 1行`、必要に応じて小さく見せる写真は `1列 x 1行` とし、一覧では `cover` 表示にする。
- 斜めカット境界線: `#F3B8C8`、4px、opacity 0.82
- 円形くりぬき枠線: `#C8DFF2`、4px、opacity 0.86
- 左右分割境界線: `#C7E6DC`、6px、opacity 0.88
- 撮影中メッセージ背景: `rgba(255, 250, 252, 0.72)`
- 撮影中メッセージ枠線: `rgba(243, 184, 200, 0.70)`
- 撮影中メッセージ文字: `#4D4650`

赤系の警告色は、カメラ体験の通常フローでは使いません。

## ワイヤーフレーム記法

ラフなワイヤーフレームは fenced code block で書きます。

例:

```text
+--------------------------------+
| ヘッダー                       |
+--------------------------------+
|                                |
| メインコンテンツ / カメラ表示  |
|                                |
+--------------------------------+
| サブ操作          | 主要操作   |
+--------------------------------+
```

ワイヤーフレームでは、見た目の装飾よりも、配置と操作の意図を短く表現します。

## テキストとローカライズ

- 新しい文字化けを増やしません。
- 日本語 UI は、対象体験に必要な文言として意図的に書きます。
- ユーザーに見える文言は短く、レビューしやすくします。
- 本番リリース前に、ローカライズ方針を改めて決めます。
