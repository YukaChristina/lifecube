# UIデザイン方針

## 位置づけ

この文書は、LifeCube のUIデザイン上の判断をまとめます。

現在の画面には、Expo スターター由来の UI と、実験的なカメラ・ギャラリー・音声認識フローが混在しています。現状の見た目は暫定として扱い、MVP ではカメラ、アルバム、ホームに整理します。

## デザイン方向性

候補キーワード:

- Quiet Pastel
- Soft Editorial

静かでかわいいが、幼すぎない。SNS に投稿しても大人が恥ずかしくない温度感を目指します。

避ける方向:

- SF感
- 儀式感
- 幼いかわいさ
- 強い警告色
- 写真を覆い隠すUI

写真に絡むUI、撮影中メッセージ、合成境界線にはパステルカラーを使います。アルバムやホームは、パステルだけに寄せすぎず、もう少し大人びた静かな質感にします。

## 当面の UI 原則

- モバイルファーストで設計します。
- 主要操作は、可能な範囲で片手でも届きやすくします。
- ネイティブアプリらしい自然な操作感と、予測しやすいナビゲーションを優先します。
- プロダクトの個性が明確になるまでは、装飾的な UI を増やしすぎません。
- カメラ、マイク、音声認識、メディアアクセスでは、権限・読み込み・エラー状態を明確に設計します。
- カメラ映像や写真に重なるUIは、透明度を高めにし、完全に見えなくなる領域を作りません。
- 音声認識中や待機中の表示は控えめにします。
- 実際の失敗状態はやや強調しますが、真っ赤な警告のような世界観を壊す表現は使いません。

## 暫定カラーと線

合成境界線と撮影中UIは、以下を初期値として実装します。写真との相性を見て後から調整します。

- 斜めカット境界線: `#F3B8C8`、4px、opacity 0.82
- 円形くりぬき枠線: `#C8DFF2`、4px、opacity 0.86
- 左右分割境界線: `#C7E6DC`、6px、opacity 0.88
- 撮影中メッセージ背景: `rgba(255, 250, 252, 0.72)`
- 撮影中メッセージ枠線: `rgba(243, 184, 200, 0.70)`
- 撮影中メッセージ文字: `#4D4650`

赤系の警告色は、カメラ体験の通常フローでは使いません。

## ワイヤーフレーム記法

ラフなワイヤーフレームは fenced code block で書きます。

例:

```text
+--------------------------------+
| ヘッダー                       |
+--------------------------------+
|                                |
| メインコンテンツ / カメラ表示  |
|                                |
+--------------------------------+
| サブ操作          | 主要操作   |
+--------------------------------+
```

ワイヤーフレームでは、見た目の装飾よりも、配置と操作の意図を短く表現します。

## テキストとローカライズ

- 新しい文字化けを増やしません。
- 日本語 UI は、対象体験に必要な文言として意図的に書きます。
- ユーザーに見える文言は短く、レビューしやすくします。
- 本番リリース前に、ローカライズ方針を改めて決めます。
